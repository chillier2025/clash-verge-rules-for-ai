# Clash Verge Rev 快速开始

## 1. 导入订阅

在“订阅”页输入你自己的订阅链接并导入。订阅链接只保存在本机，不要复制到 GitHub Issue、截图或公开文档。

## 2. 导入规则增强

打开订阅卡片菜单中的“编辑规则”，把仓库的 [`规则.txt`](../规则.txt) 作为规则增强内容导入。它使用 `prepend`，意味着这些规则会放在订阅原有规则前面。

规则动作说明：

- `PROXY`：交给名为 `PROXY` 的代理组。若订阅没有这个组，请在 Clash Verge 中把动作改为实际的代理组名，例如 `AI` 或 `Proxy`。
- `DIRECT`：直连。这里仅用于中国大陆域名/地址和明确列出的本地服务。
- `REJECT`：拒绝匹配的 UDP 请求，用来避免 QUIC/UDP 走出预期链路。

## 3. 配置全局 Merge

在“订阅”页的“全局扩展覆写配置”卡片中选择 `Merge`，粘贴 [`全局扩展覆写配置.txt`](../全局扩展覆写配置.txt)。Clash Verge Rev 会把 Merge 深度合并到运行时配置；它不是单独的 `config.yaml`，不能替代订阅节点和代理组。

本文件使用当前 mihomo 常见的 `dns` 与 `sniffer` 字段。若你的内核版本不支持某个字段，先从日志确认，再按该版本文档调整；不要把多个版本的 DNS 配置混在一起。

## 4. 开启 TUN

在“设置 → 系统设置”打开“虚拟网卡模式（TUN）”，按系统提示授权。首页“网络设置”应显示 TUN 已启用。规则模式用于按域名和进程分流；全局模式会把流量统一交给当前代理策略，排错时可临时使用。

启用后建议重新打开终端，再执行 CLI。个别程序会自行读取 `HTTP_PROXY`/`HTTPS_PROXY`，或使用独立网络栈；遇到这种情况，以 Clash 日志和实际出口为准。

## 5. 配置链式代理

链式代理面板的两项含义：

1. **入口**：当前网络可以连接的 VPS 或订阅节点；它负责把流量带出本地网络。
2. **出口**：合法授权的住宅宽带 IP；目标服务最终看到这个出口地址。

按截图所示，按顺序点击入口节点和出口节点，形成“入口 → 出口”。不要把住宅节点当作入口，也不要在仓库中记录节点地址、账号和密码。先分别测试两节点，再启用链路；延迟、UDP 支持和 DNS 解析失败都可能让链路不可用。

## 6. 验证

```bash
curl -4 https://ifconfig.me
curl -I https://api.anthropic.com
curl -I https://api.openai.com
```

同时查看 Clash 日志。日志应显示目标域名命中 AI 规则并使用代理组；若显示 `DIRECT`，检查规则顺序、代理组名称和 TUN 是否开启。公网 IP 检查只能证明出口地址，不能证明某个平台一定会接受该地址或账号。

## 7. 常见问题

### 规则导入后提示找不到 `PROXY`

你的订阅没有名为 `PROXY` 的代理组。把规则中的 `PROXY` 替换为现有代理组名称，或在订阅配置中创建一个名为 `PROXY` 的 `select` 组。

### CLI 仍然直连

确认 TUN 已启用、CLI 进程没有关闭系统网络、规则没有被更早的 `DIRECT` 命中，并检查 `PROCESS-NAME-REGEX` 是否匹配当前系统的真实进程名。域名规则通常比进程名规则更可靠。

### 链式代理超时

先关闭链式代理测试出口单跳，再测试入口单跳。两跳都能用仍超时，重点检查出口是否支持目标协议、UDP 是否被拒绝、DNS 是否能解析出口节点域名，以及两跳的服务商是否允许转发。
