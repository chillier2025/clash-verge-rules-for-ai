# Clash Verge AI 编程工具分流规则

面向 Claude CLI、Codex、OpenAI、Anthropic 及相关开发工具的 Clash Verge Rev 分流示例。项目提供一份规则增强文件和一份全局 Merge 覆写文件，帮助把指定的域名与进程交给你选择的代理组，并在 TUN 模式下让命令行程序也遵循同一套路由。

- 这是一套**路由与 DNS 配置示例**，不能保证任何服务的账号地区资格、风控结果、可用性或速度。
- 代理出口必须来自你有权使用的服务，并遵守当地法律、网络服务商条款以及 Claude、OpenAI 等服务的使用条款。
- 不要把订阅链接、节点密码、私钥、Cookie、控制器密钥或个人日志提交到 Git。仓库中的示例均不包含真实节点。
- “入口 → 出口”的链式代理只改变连接路径；出口 IP 的归属、信誉和稳定性仍由出口服务商决定。请自行确认住宅 IP 的授权、独享范围、带宽和隐私政策。

## 三分钟快速开始

1. 安装与你系统匹配的 [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev)，导入你自己的订阅。
2. 在订阅卡片菜单中打开“编辑规则”，导入 [`规则.txt`](./规则.txt)。如果你的版本只支持粘贴，请复制文件内容；不要把它当作完整配置导入。
3. 在“全局扩展覆写配置”中选择 `Merge`，粘贴 [`全局扩展覆写配置.txt`](./全局扩展覆写配置.txt)。保存后更新订阅。
4. 在“设置 → 系统设置”打开“虚拟网卡模式（TUN）”。首次启用时按系统提示授权网络扩展/管理员权限；系统代理可按需要开启。
5. 在“代理”页选择可用的代理组。若使用链式代理，先在右侧添加入口节点，再添加出口节点，检查入口和出口延迟后保存。
6. 用日志和下方验证命令确认请求确实经过预期出口，再运行 CLI 工具。

## 为什么规则这样写

规则文件把 AI 服务常见域名、遥测域名和相关命令行进程指向 `PROXY`。文件开头的 UDP 规则会拒绝这些域名的 UDP 流量，避免 QUIC/UDP 绕过后续的 TCP 代理规则；如果你的节点明确支持并且需要 UDP，可以删除对应的 `REJECT` 行，再单独测试。

规则是**首条命中**：请确保订阅自身的规则没有在它们之前把这些域名送到 `DIRECT`。`PROCESS-NAME-REGEX` 对不同操作系统、应用打包方式和进程名可能表现不同，因此 TUN 和域名规则是主要保障；命令行工具可能还需要把 `node`、运行时进程或实际可执行文件加入规则。

## 链式代理的连接关系

链式代理示意为：

```text
本机 → 入口（能从当前网络连通的 VPS/订阅节点） → 出口（你合法购买的住宅 IP） → 目标服务
```

在 Clash Verge 的链式代理面板中，按界面提示**先点入口，再点出口**。入口解决“从当前网络连到外网”的问题，出口决定目标服务看到的公网地址。两跳都会增加延迟，任一跳超时都会导致请求失败；请分别测试单跳，再测试链路。

## 验证与排错

```bash
# 查看公网出口（任选其一）
curl -4 https://ifconfig.me
curl -4 https://ipinfo.io/json

# 检查域名解析和 HTTPS 连通性
curl -I https://api.anthropic.com
curl -I https://api.openai.com
```

在 Clash Verge 日志中确认：

- 请求命中了 `PROXY` 或你自定义的 AI 代理组；
- 没有同一域名先命中 `DIRECT`；
- 链式代理的入口、出口均有连接记录；
- CLI 使用的进程确实经过 TUN（部分应用会自行设置代理或使用独立网络栈）。
